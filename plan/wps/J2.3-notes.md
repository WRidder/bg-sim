### 1. Interfaces

### 2. `@events` lowerings (plan 5.8, D19)
- `cond => begin … end`; `cond` is a real expression `c` (fires on **upward** zero crossing) or
  a comparison `a < b` / `a > b`, normalized to `c = b - a` / `c = a - b`.
- Lower to `SymbolicContinuousCallback(c ~ 0; affect = ...)` so only the rising edge fires.
  `julia/BGSim/NOTES.md` records that `affect` is the rising edge and `affect_neg` the falling
  edge, both defaulting to `nothing`, and that **affect equations must use `Pre(...)`** or MTK
  silently solves the simultaneous system (the `Pair` form auto-wraps).
- `reinit(x, v)` becomes `x ~ v` in the affect with `Pre(...)` values.
- An affect that touches a discrete variable uses `ImperativeAffect`; NOTES.md has the exact
  signature and the `modified`/`observed` named tuples. Probe it if anything is unclear.
- Fallback if a one-directional affect proves unreliable: a two-sided event with a guard
  (`Pre(c_prev) < 0`) — plan section 11 — but first try the documented one-directional form.

### 3. Nonsmooth conditions (plan 5.8)
Collect the switching conditions from `ifelse`, `abs`, `sign`, `min`, `max`, `clamp`, `floor`,
`ceil`, `round`, `saturate`, `deadzone` in continuous equations and add each as a
**condition-only** event (`SymbolicContinuousCallback(c ~ 0)`, no affect) so the integrator
lands on the switching instants. NOTES.md confirms MTK adds none of these by itself and that a
condition-only callback does land on the kink.
Do it in the lowering pass from the AST plus the `FlatEq` expressions — a structural walk over
the flattened equations is fine and simpler than inspecting Symbolics.

### 4. Recording and W206
- Event instants are recorded twice, as left and right limits with the same `t` (plan 3.5), so
  steps render as vertical edges. Coordinate with J2.2's recorder: expose
  `record_event(time, states..., :left/:right)` or write both rows through the recorder API
  that J1.5/J2.2 provide.
- **W206** when the event limit is reached (Zeno). `event_limit` comes from the model settings
  (default 10000). Count callback firings; when the count exceeds the limit, stop with a
  `retcode` that maps to W206 (a warning, not E901) and record it in the manifest diagnostics.
  NOTES.md gotcha 7 is exactly this: an `ifelse` guard on the watched variable caused 66 662
  firings — W206 must catch that, not crash.
