## Orchestrator notes

### 1. What J1.2 already gives you
`src/units/unitcheck.jl` already has:
- `Units.unit_env(pb)` — the per-declaration `Dims` environment of a block;
- `Units.conversion_factor(from::Dims, to::Dims) -> Union{Float64,Nothing}` — the factor for
  a same-dimension pair, `nothing` for a mismatch;
- `Units.substitute_domain(dims::Dims, domain::Symbol) -> Dims` — D9 (`effort`/`flow` slots →
  the concrete domain's units);
- `Units.unit_string(dims)` — canonical string (`N*m` prints as `J`), and the messages already
  name both units.
So this WP is about **wiring those into the model level**, not re-implementing parsing.

### 2. What is missing and is yours
1. **Connection unit factors (plan 5.3, last bullet).** For every **signal** connection, compare
   the output's unit with the input's unit:
   - same dimension, different scale → insert a constant factor on that connection and return
     it in `model_check.unitFactors[connId]`;
   - different dimension → **E102** on that connection id, with a hint naming both units.
   The factor must actually be applied to the generated equation (the connection equation
   becomes `input = factor * output`), not merely reported, otherwise the model is numerically
   wrong. `X2.3`/`W2.3` rely on the badge `×0.001` matching a real factor.
2. **Generic substitution after adoption (D9).** Once `domains.jl` adopts a domain for a bond
   island, substitute `effort`/`flow` in every Generic block's declared units and re-run the
   block's unit check with the substituted units. A `C` on an Electrical island must report its
   `c` unit as `F`; on Translation as `m/N`; on Rotation as `rad/(N·m)`. This requires the
   flattener to pass the adopted domain back into the per-instance unit environment — a clean
   seam in `src/compile/instantiate.jl`/`domains.jl` that J1.4 may have left open. Coordinate:
   you own `src/units/` **and** you may edit the unit-related parts of
   `src/compile/{instantiate,domains,pipeline}.jl`; keep the diff minimal and say exactly what
   you changed.
3. **E006 messages naming both units** — J1.2 already does this at block level; make sure the
   model-level messages do too, and that a Generic block whose units became concrete reports
   the concrete unit text.

### 3. Acceptance (the gate)
- a `C` on an Electrical bond reports its `c` unit as `F` (and the model's signal list shows
  `unit = "F"` for that parameter/signal);
- a signal wire from a `mm`-declared output to an `m`-declared input produces
  `unitFactors[connId] == 0.001` **and** the simulated output is scaled by 0.001 (assert the
  number, not just the badge);
- a signal wire from an `s`-declared output to an `m`-declared input gives E102 on that
  connection;
- keeping every existing test green.
