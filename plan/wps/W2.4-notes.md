### 2. What this WP adds (plan 7.5)
1. **Multiple panels** with a synced cursor: `cursor.sync` across every panel, and the plot cursor is the **global inspect time** (other modules will read it; expose it from the store and keep it in seconds).
2. **Multiple axes** per panel: already 2 unit groups from W1.4 — complete the "suggest a new panel" path when a third group is added (the store must be able to split, and the UI must offer it).
3. **Compare runs**: pin a previous run (`data-testid="pin-run"` exists) and overlay its signals as **dashed lines in the same colour**; unpin removes them. Keep the pinned run across re-renders and zoom.
4. **Live streaming**: while a run is executing, subscribe to the plotted ids over the run WS, append the tails to the in-memory series, autoscroll unless the user has zoomed, and stop cleanly on `run.done` (then refresh the final data so the last rows are exact).
5. **Plot from the canvas context menu**: the port/bond/instance context menu offers "Plot effort / flow / power" and "Plot all outputs" (plan 7.5). The canvas is `web/src/editor/` — you may add a *menu item* there, but keep the diff to a small hook and report it; W2.1 is editing other parts of the editor concurrently.
6. **CSV export** of the plotted signals (the endpoint exists).
7. **The performance budget of 7.5** as an automated Playwright perf test in `web/tests/perf/`:
   - 20 signals × 1e6 points: after the data arrives, a zoom/pan re-render is under 50 ms;
   - 60 fps while live-streaming 10 signals.
   Generate the data with `page.route` returning a synthetic binary frame (do not commit a 160 MB fixture). Measure with `performance.now()` around the render call and assert the budget; report the measured numbers in your report.
