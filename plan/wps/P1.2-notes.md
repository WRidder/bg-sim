## Orchestrator notes

### 1. What exists
M0.4 built the backend with `worker.py` (supervisor + fake worker), `app.py` and `config.py`.
The fake worker already writes a synthetic `columns.f64` and emits `run.*` notifications.
You own `backend/src/bgsim_server/runs.py`, `decimate.py` and their tests; register routes in
`app.py` minimally.

### 2. Requirements
- `POST /api/projects/{p}/runs` — `{ model }` → `{ runId }`; create `<project>/runs/<run-id>/`,
  call `run.start` on the worker (fake or real), and fan the notifications into an
  `asyncio.Queue` per run.
- `DELETE /api/runs/{id}` — cancel (`run.cancel`).
- `GET /api/runs/{id}` — the manifest JSON (`contracts/schemas/run-manifest.schema.json`).
- `GET /api/runs/{id}/data?ids=a,b&t0=&t1=&px=1600` — binary:
  `u32 n_signals`, `u32 n_points`, then a time column and one Float64 column per signal
  (little-endian). Min/max decimated to at most `2*px` points per signal over `[t0, t1]`;
  `px=0` returns raw data. Event duplicates must be preserved.
- `GET /api/runs/{id}/export.csv?ids=` — CSV export.
- `WS /ws/runs/{id}` — phases, progress, done, plus a live decimated tail for subscribed
  signal ids (`{subscribe: [...]}`), no more than 20 messages per second.
- Run history pruning (keep the last 20 per model, configurable) — do it in this WP.
- `decimate.py` per plan section 6: `numpy.memmap` on `columns.f64`, `searchsorted` for
  `[t0, t1]`, per-pixel-bucket min/max through `np.minimum.reduceat`/`np.maximum.reduceat`,
  first and last points kept, event duplicates kept. Target: 1e7 points × 10 signals under
  50 ms. **Measure it and report the number.**
  The decimation function must be pure (arrays in, arrays out) so it can be tested against a
  brute-force reference.

### 3. Tests
pytest with the fake worker for every endpoint; a `decimate` unit test against a brute-force
reference on random data with injected spikes and duplicated `t` (event) rows; a performance
test asserting the section 6 target with `time.perf_counter` on generated data (mark it so it
can be skipped on a slow machine if it is flaky, but it must pass here — measure and report);
a WS test for phases/progress/subscribe. Do not require Julia.
