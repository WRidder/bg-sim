## Orchestrator notes

### 1. What exists
M0.5 built the Vite + React + TS app: `web/src/{app,api,theme}`, `vite.config.ts` (proxy for
`/api` and `/ws` to `127.0.0.1:8765`), `eslint.config.js`, `vitest.config.ts`,
`playwright.config.ts` (webServer = `uv run bgsim`, `BGSIM_FAKE_WORKER=1`), `tests/e2e/smoke.spec.ts`
and `src/contracts/` (generated types — never edit).
The backend serves `contracts/fixtures/catalog/valid/catalog.min.json` through `catalog.get`
in fake mode (read `backend/src/bgsim_server/worker.py` to see the exact shape), and
`GET /api/catalog?project=` proxies it.

### 2. Deliverables
- `web/src/library/`: the library browser — groups from the catalog (`group` field), search,
  parameter/port summary, drag-to-add (HTML5 drag with a typed payload).
- `web/src/state/`: the zustand + immer document store. **Undo/redo is designed in, not
  bolted on** (plan 7.4): every mutation is an immer-producing command; keep patches on a
  history stack of 200; `undo()`/`redo()`; selection state is separate from the document.
- `web/src/editor/`: the xyflow canvas.
  - custom node types: block, junction (`0`/`1` circle), subsystem;
  - port glyphs per plan 7.3 (filled square = power, hollow triangle in = input, filled
    triangle out = output, double outline for vector ports), domain letter on hover;
  - bond graph letters rendered in a serif font (`C`, `I`, `R`, `Se`, `MSf`, …);
  - SVG icons in `web/src/editor/icons/` for the M1 iconic blocks (resistor, capacitor,
    inductor, ground, sources, mass, spring, damper, fixed, inertia, gear, motor, sensors) —
    one per catalog `icon` id; keep them simple and legible at 40 px;
  - bonds with a half arrow at the `to` end, wires orthogonal with a dot at 3+ ports,
    signals with an arrowhead and the plan 7.3 line styles;
  - drag from the library to add, move, delete (Del), rotate (R), flip (F), multi-select,
    copy/paste (Ctrl+C/V with renaming), reverse bond from the context menu;
  - **connection compatibility rules as a TS port of plan 5.5/5.6** (kind, domain, type, size,
    single source) with the exact refusal messages of plan 7.3, e.g.
    "Electrical port cannot connect to Rotation; use a converter (DC motor, EM converter)",
    "Input u already has a source", "Bool cannot connect to Real; insert a Type conversion".
    Incompatible ports fade while dragging; compatible ones highlight.
- Save/load through the API: `GET/PUT /api/projects/{p}/models/{m}` (P1.1) with debounced
  auto-save and a dirty marker; a "Saved" indicator.

### 3. Tests
- vitest for the compatibility rules: **one test per rule with the exact message string**, plus
  store tests for undo/redo (10 operations), copy/paste renaming, and bond reversal.
- Playwright (`tests/e2e/canvas.spec.ts`, against the fake worker): drag the DC motor iconic
  model together (VoltageSource, DCMotor, Ground, 2 Fixed shafts, damper), save, reload, and
  assert the document is identical; then 10 undo operations return to the start state.
  Use `data-testid` hooks and expose `data-state` on nodes for assertions.

### 4. Acceptance you must run yourself
```
npm --prefix web run typecheck
npm --prefix web run lint
npm --prefix web run test -- --run
npm --prefix web run build
npm --prefix web run e2e
uv run tools/check.py --lane w
```
The e2e run needs `uv run bgsim` with `BGSIM_FAKE_WORKER=1`; M0.4 provides it.
