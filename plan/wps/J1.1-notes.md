## Orchestrator notes

### 1. You own the two shared interfaces of the whole Julia lane. Pin them down.
Later WPs (`J1.2` units, `J1.3` catalog, `J1.4` flatten, `J1.6` worker, `J2.x`) are written
against what you produce. So:

**(a) `src/diagnostics.jl` — the `Diagnostic` type (plan 3.4).** Implement exactly:

```julia
struct SourceRange; file::String; line::Int; col::Int; endLine::Int; endCol::Int; end
struct SourceRef;   kind::String; ref::String; range::Union{SourceRange,Nothing}; end
struct Related;     path::Union{String,Nothing}; message::String; end

struct Diagnostic
    code::String
    severity::String                 # "error" | "warning" | "info"
    message::String
    hint::Union{String,Nothing}
    path::Union{String,Nothing}
    block::Union{String,Nothing}     # block ref, e.g. "stdlib:bondgraph/C"
    scope::Union{String,Nothing}     # e.g. "@equations"
    source::Union{SourceRef,Nothing}
    node::Union{String,Nothing}
    connection::Union{String,Nothing}
    related::Vector{Related}
end
```
- `severity` is derived from the code by one table, not passed by hand:
  `E*` → "error", `W*` → "warning", everything else → "info". Provide
  `severity_of(code)::String`.
- Provide constructors that keep call sites short:
  `diag(code, message; hint=nothing, path=nothing, block=nothing, scope=nothing,
  source=nothing, node=nothing, connection=nothing, related=Related[])` and
  `diag(code, message, parsed::ParsedBlock, node::SyntaxNode-ish; scope=...)` that fills
  `block` and `source` from the block and the node's range.
- Provide `to_namedtuple(d)::NamedTuple` / `to_dict(d)::Dict{String,Any}` producing exactly the
  JSON shape of plan 3.4 with `nothing` → `null`, for the worker (JSON3) and for
  `model.check`. Provide `from_dict(::Dict)` too, so J1.6 can round-trip.
- Provide `sort_diagnostics(v)` ordering by (path, line, col, code) so output is deterministic.
- A test asserts `to_dict` against
  `contracts/fixtures/diagnostic/valid/diagnostics.sample.json` field names (read the fixture
  and check every key of every item is representable by your type, and that your `severity`
  matches the fixture's).

**(b) `src/syntax/` — the AST and the public entry points.** The AST must be small, immutable
and documented in a comment at the top of `src/syntax/ast.jl`, because `src/units/` (J1.2) and
`src/ir/` (J1.4) walk it. Required public API (exported from `BGSim`):

```julia
parse_block(text::AbstractString; filename="<inline>", ref="inline:x") -> ParsedBlock
check_block(pb::ParsedBlock) -> Vector{Diagnostic}          # E000..E006, W204; E006 via Units
block_interface(pb::ParsedBlock) -> NamedTuple             # the catalog interface of plan 3.2
block_equations(pb::ParsedBlock) -> Vector{Any}            # checked equation AST, or empty on error
```
and these accessors over the AST (so nobody reaches into fields directly):
`block_name(pb)`, `block_ref(pb)`, `block_source(pb)`, `scopes(pb)`,
`declarations(pb, scope::Symbol) -> Vector{Decl}`, `equations(pb)`, `causality(pb)`,
`ports(pb)`.

`Decl` must expose `decl_name`, `decl_type` (`:Real`, `:Int`, `:Bool`, `Vec{N}`, `Mat{N,M}`,
`Power{Domain}` — as data, not strings), `decl_default` (an AST expression or `nothing`),
`decl_attrs` (a `Dict{Symbol,Any}` with `:unit`, `:min`, `:max`, `:tunable`, `:description`,
`:nominal`, `:state`, `:options`, `:structural`), and `decl_range::SourceRange`.
Expression nodes carry `SourceRange` too. Use one abstract type `Expr` for expression nodes
(`Lit`, `Name`, `Call`, `BinOp`, `UnOp`, `Index`, `VectorLit`, `MatrixLit`, `IfElse`,
`Comparison`, `BoolOp`) with `expr_range(e)`.

**Do not change these names later.** They are the contract for J1.2/J1.3/J1.4.

### 2. Parse with JuliaSyntax, never `eval`
`JuliaSyntax.parseall(SyntaxNode, text; filename, ignore_errors=false)`; walk the `SyntaxNode`
tree; convert to your AST. Parse errors → `E000` with the parser's range and message. Never
call `eval`, `Meta.parse`-and-eval, or `include` on user text. `JuliaSyntax` 1.0.2 is
installed; check its `SyntaxNode` API in the installed source (`~/.julia/packages/JuliaSyntax`)
before you write the walker — the `kind`, `children` and `span`/`range` accessors matter, and
`JuliaSyntax.SyntaxNode` has changed shape between versions.

### 3. Scope of J1.1
- Scopes: `@constants @parameters @inputs @outputs @ports @variables @equations @causality`
  (that is this WP's list). `@initial`, `@discrete`, `@events`, `@components`,
  `@connections` are J2.1/J2.6: they must be *rejected* with a clear `E001` naming the scope
  as not yet supported, not silently ignored. Say that in your report.
- Types Real, Int, Bool. `Vec`/`Mat`/`Power{...}` must parse and appear in the AST
  (the spec's `C` and `GearBacklash` need `Power{Rotation}`), and `Vec`/`Mat` *checking*
  (sizes, indices) is J2.1: accept the syntax, produce `E005` for a non-static size, and
  reject an out-of-range literal index only when the size is known. Be explicit in the report
  about exactly which of E005 you implemented.
- E000 syntax, E001 syntax-not-allowed-in-scope, E002 function not on the whitelist (the
  whitelist table lives in `src/syntax/whitelist.jl` — one row per spec table line, with
  allowed scopes and a lowering rule tag), E003 undeclared/shadowed name (names are local, `t`
  is predefined, `p.e`/`p.f` for ports, shadowing a whitelisted function is E003 with
  "shadows built-in"), E004 type mismatch, E005 size, W204 unused declaration. E006 comes from
  `src/units/` — call `BGSim.Units.check_units(pb)` if that module exists, and make the call
  tolerant while J1.2 is not done (a `isdefined`/`try` guard is acceptable *only* for the
  `Units` hook, and must be removed by J1.2's own WP if it wants to).
- `@causality` syntax per plan D6: `@causality p => :effort_out`,
  `@causality p => (:effort_out, :fixed)`, `@causality (p1, p2) => :transformer`,
  `@causality (p1, p2) => :gyrator`. Store it; SCAP is J2.4.
- Balance precheck of plan 4.4 (E103 at block level, reported as a warning when checked alone):
  `#equations = #variables + #outputs + #powerports`, scalars only for now, `ddt(x)` not an
  unknown, discrete excluded, `if` counts its branch, `for` unrolled. Include the three worked
  counts (`C` = 2, `GearBacklash` = 5, `PIController` = 2) as tests. Note: `C` has one
  variable and one port, so 2; `GearBacklash` has phi/w/T and ports a/b, so 5.
- Also implement the "use `~` for equations" hint (D1): `=` inside `@equations` gives `E001`
  with that exact hint text.
- `block_interface` must produce the catalog interface of plan 3.2
  (`constants`, `parameters`, `inputs`, `outputs`, `ports`, `variables`, `causality`) with
  `type`, `size`, `unit`, `default`, `min`, `max`, `tunable`, `description`, `options`,
  `start`, `state` fields — J1.3 turns it into `catalog.get` output, so get it right now.
  `size` is `[]` for a scalar and `[N]`/`[N,M]` for Vec/Mat.
