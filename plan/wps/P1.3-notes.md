## Orchestrator notes

### 1. Why this WP exists
`M0.4` delivered only `/api/health`. Plan 3.7 also requires the catalog and the two check
proxies, and the web lane needs them in M1. You are the only WP that edits `app.py`, so you
also create the empty router skeletons that P1.1 (projects) and P1.2 (runs) fill in later,
which keeps them from racing on `app.py`.

### 2. What to build
- `proxy.py` with `router = APIRouter()`:
  - `GET /api/catalog?project=<name>` → `catalog.get` with
    `params = {"projectLibraryDir": "<projects_root>/<project>/library"}` (absolute path, the
    same one the worker expects), returns the catalog JSON. Cache it in a small
    `CatalogCache` keyed by project, with an mtime-based invalidation over the library
    directory (a `watchfiles`-free implementation is fine: compare the max mtime and file
    count, or hash the file list + mtimes). A request with an unknown project → 404 naming the
    project. No `project` parameter → the stdlib catalog (`projectLibraryDir = null`).
  - `POST /api/check/block` body `{source, ref}` → `block.check`; on worker timeout → HTTP 504
    with `{"detail": "...timed out..."}`; on a worker error response → 200 with the error
    diagnostics? No: follow the worker contract — if the worker returns an error object,
    map it to HTTP 422 with `{"message", "diagnostics"}`.
  - `POST /api/check/model` body `{model, projectDir?}` → `model.check`; if `projectDir` is
    absent, derive it from the project name or use the repo root; 60 s timeout → 504.
  - Use the supervisor from `worker.py` (read its API: request/response correlation,
    `BGSIM_FAKE_WORKER`). Never spawn your own worker.
- `projects.py` and `runs.py`: **only** `router = APIRouter()` plus a one-line module
  docstring. No routes.
- `app.py`: include the three routers (proxy, projects, runs) with their prefixes; keep
  `/api/health` and the static `web/dist` mount working.

### 3. Tests
- fake worker: catalog returns 36 blocks; a second call hits the cache (assert the fake's
  request counter did not increase), then touching `library/X.jl` invalidates it; unknown
  project → 404.
- `check/model` with the diagnostics fixture returns the worker result unchanged;
  `check/block` with a small block returns `{diagnostics, interface}`.
- timeout mapping: monkeypatch the supervisor's request timeout to a few ms against a fake
  that never answers, assert 504 for both endpoints.
- existing M0.4 tests keep passing (126 + your new ones).
