### 3. `Dims` (plan 5.3)
`Dims` is an integer exponent vector over (m, kg, s, A, K, mol, cd) plus a `Float64` scale.
Implement it as an immutable struct with a tuple/`NTuple{7,Int}` of exponents and a scale;
give it `*`, `/`, `^` (integer), `==`, `isapprox`, `hash`, and a `show` that prints the unit
string. Pseudo-dimensions `effort` and `flow` (D9) are two extra symbolic slots: give them
exponents too (e.g. positions 8 and 9) so `flow*s/effort` is representable, and
`substitute_domain` replaces them: for Electrical, `effort` → V and `flow` → A; Translation,
`effort` → N and `flow` → m/s; Rotation, `effort` → N·m and `flow` → rad/s; Hydraulic,
`effort` → Pa and `flow` → m³/s. This is what makes a `C` on an electrical bond take farads
(plan J2.5 finishes the messages; you implement the substitution now).

Derived units to support: N, J, W, V, Ohm, F, H, Pa, bar, Hz, rpm, rad (dimensionless),
deg (scale π/180), mm, cm, g, min, h, L, plus the SI base units and the `s`/`m`/`kg`/`A`/`K`
forms. Parse `*`, `/`, `^` with integer exponents and parentheses; whitespace and `·` are
allowed separators. `rpm` → rad/s is a *scale* of 2π/60 with the `rad` dimension dropped;
`deg` → π/180 dimensionless; `mm` → 0.001 m; `g` → 0.001 kg; `min` → 60 s; `h` → 3600 s;
`L` → 0.001 m³; `bar` → 1e5 Pa; `Hz` → 1/s.

### 4. Checking rules (plan 5.3, exact)
- `+ - ~` and comparisons need equal dimensions (same exponents **and** same scale; a
  scale-only difference is reported as a `hint`, not an error, when both are in the same
  dimension group — decide and document).
- `* /` add/subtract exponents and multiply/divide scales.
- `^` needs an integer literal exponent.
- Functions need dimensionless arguments, except `abs sign min max clamp hypot`
  (dimension in = dimension out) and `sqrt` (halves the exponents; the exponents must all be
  even).
- Variables and parameters without a unit are **wildcards**: a wildcard term skips the check
  (this is explicitly not inference).
- Signal connections (the same dimension, different scale → a factor; different dimension →
  E102) are J2.5; implement `conversion_factor` now and test it, but the connection-level
  E102 is not yours.
- E006 messages must name both units, e.g.
  `cannot add [m/s] to [N] in "F ~ k*x + v"` with a hint naming the offending term.
