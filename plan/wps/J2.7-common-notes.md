## Orchestrator notes (common to J2.7a–g)

### 1. Where you start
J1.1–J1.5, J2.1–J2.6 have landed: the parser/checker (`src/syntax/`), units, the library
loader and catalog (`src/library/`), flattening (`src/ir/`, `src/compile/`), lowering and
simulation (`src/lower/`, `src/sim/`), the discrete scheduler, events and SCAP.
`julia/BGSim/stdlib/` already holds the 36 M1 blocks; `julia/BGSim/test/test_library.jl` checks
them all against `contracts/fixtures/catalog/valid/catalog.min.json`.
Read `julia/BGSim/NOTES.md` first, then `src/library/catalog.jl` (the group/description/icon
tables you must extend) and `test/test_library.jl` (the shape your new blocks must satisfy).

### 2. What "done" means for every block (plan section 8)
For **each** block you add:
1. `stdlib/<group>/<Name>.jl`, one `@block` per file, file name == block name.
2. Every parameter has a `description`; units use the project's unit strings; sizes are static.
3. `block.check` reports **zero** errors and zero warnings for the block.
4. A golden test in `test/golden/<group>/test_<Name>.jl` with either an analytic solution or a
   hand-written MTK reference model, within `rtol 1e-6`. Build it from the language source
   through the real pipeline (`flatten` → `lower` → `simulate`) — not by hand-writing the
   equations in Julia, and not through MTK directly. That is the point of the test: it proves
   the block compiles and simulates.
5. The catalog grows: add the block's group/description/icon/release metadata to
   `src/library/catalog.jl` and extend `test/test_library.jl`'s coverage list.
6. `test/runtests.jl` includes your golden test files (one `include` per file or a directory
   walk; re-read the file immediately before editing it — other J2.7 WPs run at the same time).

### 3. Rules that apply across groups
- **No strings.** Enumerations are `Int` with an `options` attribute (D11); selecting signs is
  `Vec{N}` of ±1.
- **Nonsmooth blocks** (`Saturation`, `Dead zone`, `Rate limiter`, `Relay with hysteresis`,
  `Hard stop`, `Friction`, `GearBacklash`, `Orifice`) must use the whitelisted nonsmooth
  forms so J2.3's condition extraction finds their switching instants. Do not hide a switch
  inside a function the event collector cannot see.
- **Nonsmooth-but-smooth option**: `Friction` uses `tanh(v/v_eps)` when `v_eps > 0`, else the
  `ifelse` switch (plan section 8).
- **Orifice** is the regularized form
  `Q = Cd*A*sqrt(2/rho) * dp / (dp^2 + p_tr^2)^(1/4)` — never a bare `sqrt(dp)`, which has an
  infinite derivative at zero.
- **Transport delay** uses the `delay` intrinsic (D12: a variable-step implementation with a
  history buffer and interpolation) and is flagged **experimental** in its description.
- **Lookup 1D/2D** use `interp1`/`interp2` (users may call them too).
- **Noise** uses `noise_normal(seed, k)` on a fixed clock so runs repeat bit for bit.
- **Scope** is editor-only (no simulation effect); **Recorder** is a no-op with decimation
  ignored (every signal is recorded anyway, D15).
- **Export input/output/parameter** are interface markers; `Export input` acts as a constant
  or table source in simulation.
- **Subsystem / Equation block** are not stdlib files: they are the user extension points.
  Do not write them as blocks; if the catalog needs an entry, mark it as an editor-only block
  and say so in your report.
- A block that cannot be written in the language without a new language feature is **not** this
  WP's job: report it as a language gap (with the exact construct you needed) and leave the
  block out rather than weakening the language.
