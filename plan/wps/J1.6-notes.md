## Orchestrator notes

### 1. Interfaces
- `BGSim.Library.catalog(project_dir)`, `BGSim.Compile.check_block_source(text; ref)`,
  `BGSim.Compile.model_check(md; project_dir)`, `BGSim.Sim.*` (J1.5) are yours to call.
- You own `src/worker/` **entirely**. M0.4 left a stub there (`protocol.jl`, `server.jl` with
  a `ping`-only `Worker.main()`); replace it with the real protocol. `src/BGSim.jl` includes
  `worker/server.jl` — keep that include and keep the module name `BGSim.Worker`.
- The Python side is already written (M0.4) and speaks this protocol: framing `u32 LE length`,
  `u8 kind` (0 JSON, 1 binary), payload; `{"id": n, "method", "params"}` requests;
  `{"id": n, "result"}` / `{"id": n, "error": {"message", "diagnostics": []}}` responses;
  notifications without `id`. Read `backend/src/bgsim_server/worker.py` and
  `contracts/schemas/worker-rpc.schema.json` and match them exactly — the M0.4 supervisor is
  the other half of this contract, and the marked pytest integration tests must pass.

### 2. Methods to implement (plan 3.6, complete)
`ping`, `catalog.get {projectLibraryDir}`, `block.check {source, ref}`,
`model.check {model, projectDir}`, `run.start {runId, model, projectDir, runDir}`,
`run.cancel {runId}`, `cache.clear`. Notifications: `run.phase`, `run.progress` (at most 20/s),
`run.done`, `log`.
- Requests must run concurrently: `block.check` while a run is in progress. Serve on Julia
  tasks; a run on its own task with the J1.5 cancellation flag.
- `block.check` must be under 150 ms warm (plan 5.12). Add a `PrecompileTools` workload that
  warms parse, check, catalog and a tiny RC/DC-motor compile+simulate, so the first real call
  is warm. `warm` in the `ping` reply is true once the workload has run.
- Logging goes to **stderr** only. Nothing on stdout.
- `run.start` writes the run files directly (J1.5's recorder) into `runDir` and returns
  `{"accepted": true}` immediately, then sends notifications.
