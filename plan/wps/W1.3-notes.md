## Orchestrator notes

### 1. Interfaces
W1.1 landed: the store, the canvas and the diagnostics panel's host location (the bottom dock
tab). You own `web/src/diagnostics/`. The backend proxies `POST /api/check/model` to the
worker; in fake mode it answers from
`contracts/fixtures/diagnostic/valid/diagnostics.sample.json` (read
`backend/src/bgsim_server/worker.py` for the exact response shape, and
`contracts/schemas/worker-rpc.schema.json` for the `model.check` result: `diagnostics`,
`domains`, `causality`, `unitFactors`, `signals`, `stats`).

### 2. Deliverables (plan 7.3, 7.4)
- The diagnostics panel: filter by severity, group by instance path, badge counts per
  severity, click-to-navigate (select and pan to the node, or open the code tab at the line
  when the diagnostic has a `source` range).
- Canvas markers: red outline + badge count for errors, amber for warnings, hover lists the
  messages, and a `related` list rendered as links.
- The **debounced `model.check` loop**: after every document mutation, debounce 400 ms, POST
  the model, and apply the result — diagnostics, `domains` (bond/wire colouring by adopted
  domain, dashed grey for unresolved Generic), `unitFactors` (the `×0.001` badge on signal
  wires), and `causality` when it arrives (empty until J2.4 — render nothing then).
  The canvas must never block; a stale response must be discarded (compare a request
  sequence number).
- While the worker is `starting`/`warming`, show a non-intrusive status instead of firing
  checks.

### 3. Tests
- vitest: the panel renders and filters; grouping by path; the debounce coalesces rapid edits
  into one request (fake timers); a stale response is discarded; the domain colouring maps
  each domain name to its token.
- Playwright (`tests/e2e/diagnostics.spec.ts`, fake worker): with the sample fixture loaded,
  clicking each diagnostic item selects its node and pans the canvas.
