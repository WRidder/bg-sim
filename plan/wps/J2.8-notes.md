## Orchestrator notes

### 1. What J1.5 already built
`src/compile/pipeline.jl` already contains a **structural hash** and a **compile cache** with
the `remake(prob; u0, p)` path, because J1.5's acceptance includes "a parameter-only re-run hits
the cache" and plan 5.8's 300 ms target. Your job is to complete and harden it, not to invent it:
read the file first and say in your report what was already there.

### 2. Requirements (plan 5.8)
- The cache key is the **structural** hash: block sources, constants, topology, and the
  settings that affect structure (solver **not** included; tolerances and `max_step` are not
  structural). Parameter values and start values are **not** part of the key.
- On a hit, reuse the compiled `System` **and** the `ODEProblem`, and produce the new problem
  with `remake(prob; u0, p)` (D4: every `@parameters` entry stays a runtime MTK parameter).
- On a structural edit, the key changes and the system is recompiled; the old entry must be
  evicted (bounded LRU is fine — say what bound you chose).
- The cache must survive across runs within one worker process (`cache.clear` in the worker
  protocol empties it; J1.6 wires that call).
- **Warm-up matters**: `julia/BGSim/NOTES.md` records that the *first* `remake`+`solve` after a
  parameter change pays 250–2700 ms of JIT, then 3–5 ms. The 300 ms target is therefore
  measured **after one warm-up re-run**, and the worker start-up must include one parameter
  change. Make the cache/benchmark test do the same and say so.

### 3. Acceptance
- the plan 5.12 target: a parameter-only re-run of the DC motor model starts producing data in
  **under 300 ms when warm**; measure it with `time_ns()` around the whole path
  (flatten → cache hit → remake → first recorded row), report min/median over 5 runs, and put
  the number in your report. If the target is missed, report the measured value and the
  breakdown instead of weakening the test.
- a structural edit (change a `@constants` value or add a node) invalidates the cache: assert
  the compile counter increments and the results change.
- `cache.clear` empties it.
- the DC motor results are identical before and after a parameter-only re-run path change
  (rmse 0 or exact equality on the recorded columns).

### 4. Wiring and scope
You own the cache parts of `src/compile/pipeline.jl` only. Do not change the language, the
recorder layout or the worker. `test/test_cache.jl` is new: add exactly one include line to
`test/runtests.jl` (re-read it immediately before editing — other WPs may touch it).
