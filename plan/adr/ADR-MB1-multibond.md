# ADR-MB1: multibond contracts (C-MB1)

Status: accepted, 2026-10-28 (revision 2). Scope: `contracts/` for M3, WP C-MB1.
Sources: `plan/MULTIBOND_PLAN.md` 4, 6, 7.1, 8; `plan/IMPLEMENTATION_PLAN.md` 3.2-3.4; the spec's frame discussion.

This ADR freezes the multibond decisions and the concrete contract shapes the three lanes build against. The JSON Schemas remain the single source of truth; the pydantic and TypeScript files are generated from them.

## Decisions

**D-MB1 — `Power{Planar}` / `Power{Spatial}` on the existing port abstraction.** Accepted; a second `MultiPort` would duplicate the IR, causality and editor machinery. Consequence: `DomainName` gains both names in every enum, a planar port has size 3, a spatial port size 6, and `Generic` is the only domain without a concrete unit.

**D-MB2 — angular-first `[ω; v]`, wrench `[m; f]`.** Accepted; it matches the design, the spec and Featherstone, so formulas transcribe without reordering. Consequence: component units are angular first, and the planar `ad(V)` is the spatial form restricted to the plane.

**D-MB3 — v1 inertia: body frame at the CoM on principal axes, `J::Vec{3}` and `m::Real`; full `IGeneral` later.** `M` lives only in `I`, and `Coriolis` takes the momentum `P` as a signal input, not a copy of the inertia. Consequence: `I` stays component-wise and Dzhanibekov is reachable with a diagonal inertia.

**D-MB4 — one multibond port per body; named attachment frames are external `FixedTransform`s.** Accepted; fixed-arity ports still cover arms, wheels and contacts. Consequence: no variable-arity ports or generated templates in v1; a subsystem port's declared frame is authoritative for the exposed port, and it may differ from the internal port's catalog frame only through an internal `FixedTransform`/`JointTransform`.

**D-MB5 - frame metadata + equality + `E007`; transforms are the only bridge.** Accepted; this catches the main wiring bug without dependent frame types. Consequence: optional `frame` on catalog and subsystem power ports, display-qualified `model.check.frames` values while frame equality is **face-scoped** (FIX-MB-6, see "Face-scoped frame identity" below), and no `SE3{:a,:b}` arithmetic.

**D-MB6 — only floating bases integrate a pose.** 2D angle+position; 3D quaternion+position with `ManifoldProjection`; fixed-base links compose `g_child = g_parent ∘ g(q)`. Consequence: poses fit `ODEProblem`, and `ComposePose` is a library block, not a new contract type.

**D-MB7 — one backend: the existing MTK/OrdinaryDiffEq pipeline.** Accepted because a custom articulated-body evaluator is explicitly out of scope and would be a second solver path. Compliant joints are the default; a rigid joint is a DAE handed to `mtkcompile`'s index reduction. Consequence: no articulated evaluator, and stiffness and step time remain model properties rather than contract fields.

**D-MB8 — one scalar power port per joint axis, domain from the screw, `S` a `Mat{D,n}` TF.** Accepted so the scalar unit checker can validate every drive without inventing a `JointSpace{n}` domain. Revolute exposes `Rotation`, prismatic `Translation`; a helical joint exposes its coordinate's domain and keeps the pitch in `S`. Consequence: no false unit error on a prismatic drive and no new domain.

**D-MB9 — compliance, friction and limits as per-joint variants.** A composite cannot conditionally include elements, and `k = 0` is not rigid. Consequence: separate library refs such as `Revolute2DCompliant`, with no global switch in the contract.

**D-MB10 — component-wise loops in two thin Planar/Spatial wrappers.** The unit checker is scalar, so `p.e[k]` keeps torque and force distinct. Consequence: per-component unit arrays in the catalog and at subsystem boundaries; no vector-valued unit inference in the language.

**D-MB11 — compliant `ContactPoint` in v1; `SwitchedJoint`/impact later.** Accepted because contact is buildable from existing primitives while a model-level impulse needs the corrected projection first. Fixed Hunt-Crossley and regularized-Coulomb forms ship with exposed parameters. Consequence: no contract field for mode switching; `V+ = S (SᵀMS)⁻¹SᵀMV−` waits in the plan for J-MB14.

**D-MB12 — Planar 2 strokes, Spatial 3, scalar 1, derived from the domain.** The count encodes the model dimension, not `D` (Planar has three components but two strokes). Consequence: no stroke field; `model.check.multibond` reports the count for the renderer.

**D-MB13 — real-time and export out of scope.** The adaptive stack cannot meet fixed-step, no-allocation or <1 ms targets. Consequence: `W203`/`E104` stay deferred and performance is recorded, not gated.

## Contract shapes

- `catalog.schema.json`: `CatalogDomain` is a name-partitioned union of `PlanarDomain`, `SpatialDomain` and `ScalarDomain`; an `allOf`/`if`/`then` over `name` restates the same partition. Planar requires `components` with exactly 3 units per array and `size` 3; Spatial requires exactly 6 and `size` 6; scalar domains forbid `components` and have `size` 1. The `components` arrays are authoritative; the scalar `effort`/`flow` descriptors are only the angular/first-component label kept for existing consumers. Both multibond domains declare `across = "f"` (D8). `portDecl.frame` (shared with `blockInterface`) is optional string/null, and `catalogBlock.dimension` and `blockInterface.dimension` are optional `2 | 3`.
- Planar components: effort `["N*m","N","N"]`, flow `["rad/s","m/s","m/s"]`. Spatial: effort `["N*m","N*m","N*m","N","N","N"]`, flow `["rad/s","rad/s","rad/s","m/s","m/s","m/s"]`.
- Frame rule (D-MB5): a port's frame is the frame its twist/wrench are expressed in. A subsystem port's frame is **authoritative for the exposed port**; it may differ from the internal port's catalog frame only through an internal `FixedTransform`/`JointTransform`, which the flattener must accept. `null`/absent is frame-neutral: it unifies with any adjacent frame (adopts it) and never causes E007. Two different named frames on one bond or wire are E007. `model.check.frames` values are display-qualified as `"{path}/{frame}"` (e.g. `Arm1/body`), but equality is face-scoped (see below): two primitive ports that use the same name are the same frame, two composite/subsystem faces of different instances are not.
- `model.schema.json`: subsystem power port gains optional `frame` and optional `effortUnits`/`flowUnits`, each exactly 3 (`UnitArray3`) or 6 (`UnitArray6`) strings. Its `size` is pinned to the declared domain by `allOf`/`if`/`then`: `[3]` for Planar, `[6]` for Spatial and `[1]` for the scalar domains, so `domain: "Planar", size: [4]` is invalid. Derivation of the units from the port's catalog domain is preferred; the arrays exist only when a subsystem overrides a Generic port, and J-MB1 checks equality with the domain's `components`. Its domain enum gains both multibond names.
- `worker-rpc.schema.json`: `domains` gains both names. `frames` is required and maps connection id to a display-qualified frame name (`"{path}/{frame}"`, empty object valid); equality is face-scoped (D-MB5, FIX-MB-6). Optional `multibond` maps connection id to `2 | 3`; it must agree with the adopted domain (2 for Planar, 3 for Spatial) and is reported for bonds only - J-MB1 invariant. A multibond port is recorded per component: `signals` carries `<path>/<port>.e[k]` and `.f[k]`, each with its own unit, plus the scalar `<path>/<port>.P` in W; `run-manifest`'s signal-id pattern accepts a field index.
- `diagnostic.schema.json` does not enumerate codes; the codes live in the sample fixture, both contract-test code lists and this ADR.

## Face-scoped frame identity (FIX-MB-6)

D-MB5's first implementation compared frames by the unqualified name, which accepted a direct bond between two `RigidBody2D`/`RigidBody3D` (both faces are literally `body`). The comparison is now: a claim made through a composite/subsystem **face** (a textual composite's interface port or a model-JSON subsystem port) is identified by `(instance path, name)`; a primitive port keeps its declared name. Two claims conflict when the names differ, or when **both** are faces of different instances and the name is not the global `world`. Consequences: a direct `Body1.p` to `Body2.p` bond is one E007 naming both instance paths (hint: use a joint or a frame-neutral transform); the same bodies through a `FixedJoint`/transform or any frame-neutral port are legal; `Ground(world)` still shares `world` across instances; a primitive transform's `body` side matches any body face by name; composite interiors (all primitives wired to the one face junction) are unchanged. `model.check.frames` keeps the `{path}/{frame}` shape. A face that wraps a transform and should join a named body face must be frame-neutral (a null face adopts its neighbour), which is why `model.frame-bridge.json` declares `Mount.b` without a frame. Residual limitation: two primitive (non-face) ports that both name their frame `body` are still accepted; typed frame objects (options 2 and 3 of `plan/wps/M3-frame-scoping.md`) remain deferred.

## New diagnostic codes

- **E007 — frame mismatch.** A bond or wire joins two multibond ports with different declared named frames (including the union-find over a junction or wire group). The message names both ports and both frames; `path` is the reported port, `related` names the other end of the bond, and `connection` points at the bond, so the editor can highlight both. The hint names `FixedTransform`/`JointTransform` and says a null frame unifies. Example: "frame mismatch: Planar port `p` of `Arm1` is in frame `world`, but port `a` of `Load1` is in frame `arm1`".
- **E108 — invalid inertia (parameters).** An inertia's *parameters* are invalid: `m <= 0`, a principal inertia `J <= 0`, an `IGeneral` matrix that is not symmetric positive definite, or a non-finite entry. The hint names the offending parameter and the body path; the triangle-inequality hint applies only to `IGeneral` (v1 uses a diagonal `J`). It is a parameter fault, independent of assembly.
- **E109 — singular mass (assembled).** After assembly the mass matrix of a body/subtree is singular at the current configuration although the parameters are valid - e.g. a planar body with zero out-of-plane inertia driven by a spatial wrench, or a constrained subtree that leaves a free direction. The message names the body and the singular direction; the hint asks for the missing inertia or a compliant element. It is distinct from E103 (equation balance) and E106 (fixed-causality conflict) and fires after assembly.

## Known generator artefacts (owned by C-MB2)

The generated pydantic is laxer than JSON Schema in ways the generator cannot express. Every optional field becomes `| None = None`, so it accepts an explicit `null` for, e.g., `dimension` or `multibond`, where the schema only allows absence; pydantic's lax integer coercion also accepts `"2"` for `stats.states` where the schema requires an integer. `allOf`/`if`/`then` are not translated into validators; the domain-shape partition is therefore written as a `oneOf` of concrete variants, which Python renders as a `RootModel` union and enforces structurally. C-MB2 owns tightening or adding post-validation tests for these laxnesses. TypeScript renders `CatalogDomain` as an alias of the generated `Domain` union.

## Cross-WP invariants

J-MB1: report frames display-qualified and compare them face-scoped (FIX-MB-6: `(instance path, name)` when both claims are faces, the bare name otherwise); make `multibond` agree with the adopted domain and report it for bonds only (plan 7.1: strokes are a bond property, so a Planar wire has no `multibond` entry); accept a subsystem port whose authoritative frame differs from its internal port's catalog frame only through a connected internal transform, not an unconnected one; treat a null subsystem face as frame-neutral; carry a textual composite's `@ports` frame; report a concrete override of a Generic internal port as E102 (a Generic internal port's flat ids are scalar, so only the scalar override is supported in v1); take a junction's width from the adopted domain and report a Generic scalar port on a multibond junction as E102; and check that subsystem `effortUnits`/`flowUnits` equal the catalog domain's `components`. W-MB1/W-MB2 consume `multibond` for the 2/3-stroke renderer; no stroke field is added.

### Frozen decisions as shipped

D-MB1, D-MB2, D-MB3, D-MB4, D-MB7, D-MB8, D-MB9, D-MB10, D-MB12 and D-MB13 shipped as written above. The contract shapes under "Contract shapes" are unchanged by M3; C-MB2 made only descriptive changes to the schemas (below) and added `"frame": null` to the ports of `catalog.min.json` so the fixture equals what `catalog.get` emits. The catalog holds 7 domains with exact `components` and, among the new groups, Spatial mechanics, Drives and Contact; every `Planar`/`Spatial` port in it has size 3/6 (or scalar), a matching domain entry with per-component effort/flow units, and the block's `dimension` 2/3, and no block mixes the two.

### Deviations from the plan, as shipped

- **D-MB6 / `ManifoldProjection`.** There is no `ManifoldProjection` seam in `src/sim`. The 3D pose is seven states on the chart `Vec{7} = (q_w, q_x, q_y, q_z, x, y, z)` and the right-hand side satisfies `q . qdot = 0`, so the norm is a first integral (measured drift 6e-14 .. 9e-15, asserted to 1e-9). Only floating bases integrate a pose; fixed-base poses are algebraic.
- **`JointBasis` / `JointPose3D` dropped** (the user's 2026-10-29 design correction, J-MB9). The 3D joints are 16 fixed-structure typed blocks in `stdlib/spatial/` whose axis is the local z of the joint frame, placed by `FixedTransform3D`/`FixedTransform3DNeutral`. No contract field describes a joint basis or axis.
- **Face-scoped frames** (FIX-MB-6, above) replace the first implementation's unqualified-name identity (DEC-MB-1). Residual: two primitive (non-face) ports that both name their frame `body` are still accepted. Typed frame objects stay deferred with D-MB5. `model.frame-bridge.json` has a frame-neutral `Mount.b` for this reason.
- **D-MB7 / D-MB9, compliant joints (DEC-MB-2).** A rigid joint on a multi-DOF body is index 3; the shipped joints are compliant by default and `Revolute2DRigid` reports a documented W201 set (3 momentum aliases + the joint-frame translations, not "exactly two").
- **D-MB10.** `TFPlanar`/`MTFPlanar`/`TFSpatial`/`MTFSpatial` take a diagonal `Vec` modulus; general matrices are the separate `*Mat` blocks. A whole-field equation such as `p.e ~ [F, F, F]` bypasses the per-component unit check (J-MB2 open item); write elements component-wise.
- **D-MB11 / impact.** `ContactPoint` ships with the Hunt-Crossley normal force and the **Hertz exponent fixed at 3/2** (a parameter exponent is rejected by the unit checker). The switched pivot and impact map shipped in J-MB14 with a v1 limit: the impact map applies only to bodies built with **`ImpactBody3D`** (single-body impact, sharing `sw`/`mode_new` with `SwitchedPivot3D`); there is no cross-block reinit. Pivot axes are parallel to the principal axes and the edge mode is the pivot-z hinge.
- **Chain loader** is `src/library/chain_loader.jl` (the name avoids the J1.3 `loader.jl`). SDF parsing is M5; the records map one to one onto SDF elements.
- **Catalog metadata.** `dimension` is omitted for scalar blocks (the schema allows only 2 or 3); `frame` is emitted for every port (null = frame-neutral).
- **Generated pydantic is laxer than the schema** in the ways under "Known generator artefacts". C-MB2 resolved this by adding tests, not by changing the generator: for the multibond rules (block `dimension` 4 or `"2"`, `Spatial` size 3, `Planar` size 6, `components` of the wrong length, an integer `frame`) the schema and the generated model both reject the mutation. The one remaining difference is that pydantic accepts an explicit `null` for an optional field that the schema allows only to be absent (e.g. `dimension`, `multibond`); the schema is authoritative, the worker never emits such a null, and `test_explicit_null_dimension_is_a_known_pydantic_laxness` pins both halves. The integer coercion of `stats.states` is unchanged and unreachable from a document produced by the worker.

### Contract gaps closed or recorded

- **Vector signal units (the J-MB8 "one unit slot" gap): recorded, not a schema change.** `ioDecl.unit` stays one string-or-null for the whole declaration; a vector or matrix signal such as the `u` of `SeSpatial`, the `y` of `DeSpatial`, a twist, a wrench tap or a pose has a single `unit`, which is `null` when its elements differ. Per-element units live where they are authoritative, on the power port (the domain `components` arrays and the recorded `p.e[k]`/`p.f[k]` signals). Per-element signal units would need a new array on `ioDecl`, a Julia emitter change in `src/library/catalog.jl` and unit-checker support for vector signal ports; none of that has a consumer in M3 (the editor shows port units, not signal units) and the Julia sources are outside this WP. The `ioDecl.unit` description now states the rule; the block files' own comments ("C-MB2 contract gap") describe the same limitation.
- **Pose binding order (viewer contract, for M5): fixed.** `poseBinding.signal` is exactly seven signals in the order `(q_w, q_x, q_y, q_z, x, y, z)`, quaternion first, the same order as the model's `Vec{7}` pose chart (`PoseIntegrator3D`, `ComposePose3D`, `JointTransform3D`). The schema description, `bindings.robot.json`, the E304 sample message and both contract suites (an order assertion on the fixture) say so; there is no structural change. The viewer must not reorder or infer the order from names. **The spec's binding example and its table row ("7: position + unit quaternion"; `x, y, z, qw, qx, qy, qz`) predate the chart and are superseded**; the spec file is outside C-MB2, so it is listed as a follow-up edit for the orchestrator. A planar SE(2) pose chart is `(theta, x, y)` (the `ComposePose2D`/`PoseIntegrator2D` `g`); the binding schema has no planar count yet, so a planar pose binding is an M5 decision, to be recorded when it is made.
- **Contact signal units.** `ContactPoint`/`ContactSurface` signals (`o` in m, `fr` dimensionless) are catalog `unit` strings and are covered by the same rule.
- **M2 gap 4 (Bool vector ports) and NOTE-8 (EM converter housing port)** are not contract changes and stay open as recorded in `plan/STATUS.md`.
