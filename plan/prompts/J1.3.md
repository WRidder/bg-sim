## 3. Contracts (WP C0 formalizes these as JSON Schema)

Every shape below becomes `contracts/schemas/<name>.schema.json` (JSON Schema 2020-12). Each one gets at least one valid fixture and one invalid fixture.
- Python: pydantic v2 models are generated with `datamodel-code-generator`.
- TypeScript: types are generated with `json-schema-to-typescript`.
- Julia: plain structs are parsed with JSON3. The Julia tests check them against the fixtures.

### 3.1 Identifiers and signal names
- **Instance path:** subsystem names joined by `/`, for example `Plant/Motor1`. Instance names match `[A-Za-z_][A-Za-z0-9_]*` and are unique within their diagram.
- **Signal ID:** `<instance path>/<name>` for variables, inputs and outputs, for example `Plant/Motor1/w`. Port fields use `.`: `Plant/Motor1/shaft.e`, `Plant/Motor1/shaft.f`, `Plant/Motor1/shaft.P` (the derived power).
- **Array elements:** `Ctrl/xhat[2]`, 1-based. Matrix elements: `Ctrl/P[1,2]`.
- **Block reference:**
  - `stdlib:electrical/Resistor` for the standard library;
  - `project:MyGear` for the project library;
  - `inline:<node-id>` for an equation or code block embedded in the model.

- `stream.f64`: row-major `[t, v1 … vn]` little-endian Float64 rows, appended while the simulation runs. It matches the spec's frame layout.
- `columns.f64`: written at the end. It holds the time column, then one column per signal in manifest order, each `n` Float64 values (this is the spec's playback file).
- Bool and Int signals are stored as Float64.
- Event instants are recorded twice, as left and right limits with the same `t`, so steps render as vertical edges.

### 3.6 Worker protocol (`worker-rpc.schema.json`)
- Transport: the backend listens on a random localhost TCP port and starts Julia with `BGSIM_PORT=<port>`, and the worker connects back. Each frame is a `u32 LE length`, a `u8 kind` (0 = JSON, 1 = binary) and a payload.
- Julia stdout and stderr are only logs. They are captured to `backend/logs/worker.log` and are never protocol.
- Requests: `{ "id": 17, "method": "...", "params": {...} }`. Responses: `{ "id": 17, "result": ... }` or `{ "id": 17, "error": { "message", "diagnostics": [] } }`.
- Notifications carry no `id`: `{ "method": "run.progress", "params": {...} }`.

| Method | Params | Result |
| --- | --- | --- |
| `ping` | none | `{ version, julia, warm }` |
| `catalog.get` | `{ projectLibraryDir }` | the catalog (3.2), including project blocks |
| `block.check` | `{ source, ref }` | `{ diagnostics, interface }` for the fast as-you-type pass, with a target under 150 ms warm |
| `model.check` | `{ model, projectDir }` | `{ diagnostics, domains: {connId: domain}, causality: {connId: {strokeAt: "from" or "to"}}, unitFactors: {connId: factor}, signals: [...], stats }` |
| `run.start` | `{ runId, model, projectDir, runDir }` | `{ accepted: true }`, then notifications |
| `run.cancel` | `{ runId }` | `{ ok }` |
| `cache.clear` | none | `{ ok }` |

Notifications:
- `run.phase` `{ runId, phase: "parse" | "flatten" | "causality" | "mtkcompile" | "init" | "simulate" | "write", t_s }`
- `run.progress` `{ runId, t, rows }` at most 20 per second

## 4. The language front end (applies to all J WPs)

The spec is normative. This section only adds implementation detail.

### 4.1 Parsing
- Use **JuliaSyntax.jl**: `JuliaSyntax.parseall(SyntaxNode, text; filename, ignore_errors=false)`.
- Parse errors become `E000` (syntax error) with the parser's range. (E000 is added to the code table; it is the parser stage.)
- Walk the `SyntaxNode` tree. **Never `eval` user code.** Convert it into our own AST (`src/syntax/ast.jl`): small immutable structs, each carrying `SourceRange(file, line, col, endLine, endCol)`.
- The top level is one or more `@block Name begin ... end`. Inside, only the scope macros are allowed: `@constants @parameters @inputs @outputs @ports @variables @initial @equations @discrete @events @causality @components @connections`. A scope macro may take a single declaration or a `begin` block.

### 4.2 Whitelist (per scope)
- `whitelist.jl` is the single table: syntax kind, then allowed scopes, then a lowering rule. It encodes the spec's tables "Operators and statements per scope" and "Built-in function whitelist" row by row.
- Each table row has one test, with an allowed case and a rejected case giving `E001` or `E002`.
- **Intrinsics** (D12) live in a separate table with a `stdlib_only` flag.

### 4.3 Declarations
- Form: `name::Type = default, [attrs]`. `Type` is one of `Real`, `Int`, `Bool`, `Vec{N}` or `Mat{N,M}` (M4 adds `Power{Planar}`), and defaults to `Real` when omitted.
- Port types: `Power{Domain}`.
- Attributes:
  - `unit`, `min`, `max`, `tunable`, `description`, `nominal`, `state`, `options` (D11);
  - `structural` (constants only, implied).
- Defaults are constant expressions: literals, `@constants`, other parameters, and whitelisted pure functions. They are evaluated at instantiation by a small constant-folding interpreter, never by `eval`.

### 4.4 Block-level checks (fast pass, `block.check`)
- E000 to E006 and W204.
- Name resolution (E003). Names are local; `t` is predefined; ports give `p.e` and `p.f`. Shadowing a whitelisted function gives E003 with "shadows built-in".
- Type checking (E004). Bool only in conditions and logic. Int only in discrete code, indices and constants. Real to Int never happens implicitly.
- Sizes (E005). Static indices must be in range, and `for i in 1:N` needs `N` constant.
- Units (E006). See 5.3.
- Per-block balance precheck (E103 at block level, reported as a warning when the block is checked alone). The rule:
  - `#equations = #variables + #outputs + #powerports`;
  - counting scalars, with Vec/Mat expanded;
  - `ddt(x)` does not count as an unknown;
  - discrete-scope variables are excluded;
  - `if` equations count their branch;
  - `for` loops are unrolled.

  Worked counts:
  - `C`: q, plus port p, gives 2 equations. ✓
  - `GearBacklash`: phi, w, T, plus ports a and b, gives 5. ✓
  - `PIController`: x, plus output u, gives 2. ✓

## Verified API (what section 5.8 must use)

```julia
using ModelingToolkit, Symbolics
using SymbolicIndexingInterface: getu, setu, getp, setp      # NOT exported by MTK
import SymbolicIndexingInterface
using OrdinaryDiffEqRosenbrock                                # Rodas5P, solve, init, step!
using ModelingToolkit: t_nounits as t, D_nounits as D,
    SymbolicContinuousCallback, ImperativeAffect              # public, NOT exported
```

* **Variables from strings** — `only(@variables $(Symbol(name))(t))` works inside a
  function, with no warning, and accepts a dotted bg-sim signal ID verbatim:
  `mtk_variable("motor.omega")` prints as `var"motor.omega"(t)`,
  `SymbolicIndexingInterface.getname` returns `"motor.omega"`, and two calls with the same
  string give the same variable (`isequal` is `true`). `BGSim.mtk_variable`,
  `BGSim.mtk_parameter` and `BGSim.mtk_discrete` wrap this.
  Parameters are `only(@parameters $(Symbol(name)))`, discretes are
  `only(@discretes $(Symbol(name))(t))` (a discrete is a *time-dependent parameter*:
  `isparameter` is `true`, and it belongs in the `System` parameter list).
* **System → mtkcompile → ODEProblem → solve** — `System(eqs, t, vars, pars; name = :x)`,
  `mtkcompile(sys)`, `ODEProblem(sys, op, tspan)` with **one merged operating-point map**
  (start values *and* parameter values in the same vector or `Dict`), then
  `solve(prob, Rodas5P(); abstol = 1e-10, reltol = 1e-10)`.
* **Observed values with `getu`** — `getu(indp, sym)` returns a *callable getter*, so the
  observed value is `getu(integ, y)(integ)`. `integ[sym]` and `sol[sym]` work too.
  `sol(t, idxs = sym)` interpolates. `getu(integ)` with no symbol does **not** exist; the
  state vector is `integ.u`.
* **Parameters on the integrator with `setp`** — curried: `setp(integ, V)(integ, 2.0)`,
  several at once with `setp(integ, [V, R])(integ, [3.0, 4.0])`. Read with
  `getp(integ, V)(integ)`. `integ.p[V]` does **not** work (`p` is an
  `MTKParameters`/`DespecializedParameters` struct). `setu(integ, x)(integ, 0.5)` sets a
  state.
* **One-directional continuous events** — `SymbolicContinuousCallback(cond; affect, affect_neg)`.
  `affect` fires on the rising edge, `affect_neg` on the falling edge; **both default to
  `nothing`**, so a condition-only event (no affect at all) is
  `SymbolicContinuousCallback(c ~ 0)`, and a falling-edge-only event is
  `SymbolicContinuousCallback(c ~ 0; affect_neg = [...])`. The event point is saved twice
  (`save_positions == [true, true]`), i.e. pre- and post-affect values at the same `t`.
  `rootfind = SciMLBase.RightRootFind` also works (default `LeftRootFind`).
* **Imperative affects** — `ImperativeAffect(f; modified = (; x), observed = (; y))` where
  `f(modified, observed, ctx, integrator)` returns a `NamedTuple` of the new values of the
  modified variables (no Setfield/Accessors needed). `modified` must be bare variables;
  every discrete written this way is picked up automatically, so no `discrete_parameters`
  is needed on the callback.
* **Condition-only events from `ifelse`** — MTK does **not** add callbacks for `ifelse`.
  `ODEProblem(...).kwargs` has no `:callback` unless we pass `continuous_events`, so the
  collection of switching conditions that section 5.8 describes is ours to do, and it
  works: with `SymbolicContinuousCallback(x ~ 0.5)` the solver saves a point at the kink
  (t = 0.4999993411925162, x = 0.500000658807484 with `1e-10` tolerances) and the solution
  after the kink is exact.
* **`remake`** — `remake(prob; p = [R => 2.0], u0 = [x => 0.5])` works with symbolic maps and
  leaves `prob` untouched (decision D4).

## API surprises and gotchas

1. **`Pre(...)` is required in affect *equations*.** `[v ~ -e * v]` silently solves the
   simultaneous system `v = -e*v`, i.e. it sets `v = 0` — no error, wrong physics. Write
   `[v ~ -e * Pre(v)]`. The `Pair` form `[v => -e * v]` is safe because `AssignmentAffect`
   wraps the right-hand side in `Pre` for you.
2. **`getu`, `setp`, `getp`, `setu`, `SymbolicContinuousCallback` and `ImperativeAffect` are
   not exported** by ModelingToolkit (they are `@public`). Import them explicitly from
   `SymbolicIndexingInterface` / `ModelingToolkit`. `using SymbolicIndexingInterface`
   wholesale clashes with MTK on `observed`.
3. **`getu(integ)` (no symbol) does not exist** in SymbolicIndexingInterface 0.3.55; use
   `integ.u` for the whole state vector.
4. **A discrete counter has its own timeseries.** `sol[n]` for a discrete returns one entry
   per event plus the start value (e.g. `[0.0, 1.0, …, 6.0]`), so it must not be indexed
   with an index into `sol.t`.
5. **`==` on symbolic variables builds an `Equation`**, not a `Bool`. Use `isequal`.
6. **`ODESystem` and `structural_simplify` still exist but are deprecated aliases** that emit
   a `depwarn` and forward to `System`/`mtkcompile`. Never use them.
7. **An `ifelse` guard on the contact variable causes Zeno chatter.** A model with
   `D(v) ~ ifelse(h < 0, 0.0, -g)` plus a condition-only/edge event on `h ~ 0` re-triggered
   66 662 times inside 0.45 s and ended in `retcode = MaxIters`. Keep switching guards off
   the variable that a callback watches (the WP W206 event limit is exactly for this).
8. **The first re-run after a parameter change pays JIT.** `remake` + `solve` on a freshly
   compiled model took 1.1–2.7 s the first time and 3–5 ms afterwards; reusing one
   integrator with `setp` + `reinit!` + `solve!` took 525 ms the first time and <1 ms
   afterwards. The 300 ms target of section 5.8 must therefore be measured **after** one
   warm-up re-run, and the worker's start-up warm-up should include a parameter change.
9. `ifelse` has two lazy/eager variants in SymbolicUtils (`ifelse_eager`, `ifelse_branching`,
   the latter never evaluates the untaken branch). Plain `ifelse` is the default and is
   intended to pick a strategy by heuristic later; if a branch is only valid when its
   condition holds (division by zero, `NaN`), prefer `ifelse_branching`.
10. `System` accepts a `Dict` for the operating-point map as well as a vector of pairs.
